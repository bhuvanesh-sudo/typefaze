# TypeFaze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser app where a visitor draws 5 letters (or uploads a font), a from-scratch flow-matching model generates all 52 Latin letters in that style client-side, and the visitor downloads an installable `.otf`.

**Architecture:** A Python package (`typefaze/`) renders Google Fonts (OFL) glyphs to 64×64 bitmaps, trains a style encoder + conditional U-Net with a rectified-flow objective on Kaggle, exports both to ONNX, and evaluates against a nearest-font retrieval baseline. A React + Vite app (`web/`) runs the encoder and the Euler sampling loop with ONNX Runtime Web (WebGPU, WASM fallback), traces bitmaps to outlines, and builds the font with opentype.js. The retrieval baseline ships first as a placeholder generator behind the same interface.

**Tech Stack:** Python 3.11, PyTorch 2.x, Pillow, NumPy, onnx, onnxruntime, pytest · TypeScript, React 18, Vite, onnxruntime-web, opentype.js, a potrace-family tracer, Vitest

**Spec:** `docs/superpowers/specs/2026-11-20-typefaze-design.md`

**Workflow:** Claude writes and tests code in its workspace and syncs it to the user's repo at `C:\Projects\typefaze`. The user pushes to GitHub and runs the Kaggle steps (Tasks 3 and 6). Walkthrough checkpoints are blocking: don't start the next task until the user has explained the component back.

## Global Constraints

- Character set and order: `CHARS = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"` (52). The index into this string is the `char_id` everywhere, in both Python and TypeScript.
- Reference letters: `REF_CHARS = ["H", "O", "n", "a", "g"]`.
- Bitmap: 64×64. Stored as uint8, 0 = paper, 255 = ink. In model space, float in [-1, 1] with ink = +1 and paper = −1.
- Rendering convention (shared by fonts, drawings and uploads): em size = 48 px, baseline at row 50 (0-indexed from the top), each glyph horizontally centred on its advance width at column 32. A font is dropped if more than 2% of the ink in its 52 glyphs falls outside the box.
- Guide lines (in 64-px units): baseline row 50, x-height row 26, cap-height row 16, descender row 62.
- Training data: `google/fonts` `ofl/` directory only. Families = subdirectory names. Split by family 90/5/5 with seed 0.
- Model: 10–25M parameters in total (encoder + U-Net). Flow matching with x₀ = noise, x₁ = data, xₜ = (1−t)·x₀ + t·x₁, target velocity x₁ − x₀. Euler sampling, default 12 steps (allowed range 8–16).
- In the browser: no server calls for inference. Total model download < 30 MB (fp16 first, int8 only if over). Must work when WebGPU is unavailable (WASM).
- Training must checkpoint at least every 30 minutes.
- Font output: unitsPerEm 1000; 1 px at 64-scale = 1000/48 font units; y in font units = (50 − row) × 1000/48.

## Review Focus

1. **Generate pressed with fewer than 5 letters drawn.** Expect Generate to be disabled, with a note saying which letters are still missing. *(Task 7)*
2. **A drawing that goes outside the guide box, or is tiny.** Expect it to be accepted without crashing, with ink outside the 64×64 box clipped and a visible warning. *(Task 7)*
3. **A browser without WebGPU** (some Firefox and Linux setups). Expect generation to still complete via WASM. *(Task 10)*
4. **An uploaded font that is invalid, or lacks one of H O n a g.** Expect a clear error message and no crash. *(Task 7)*
5. **A generated glyph that comes out blank or solid ink.** Expect tracing to return a valid (possibly empty) outline and the font to still build and install. *(Task 9)*

### Task 4: Model

**Files:**
- Create: `typefaze/augment.py`, `typefaze/model.py`
- Test: `tests/test_model.py`

**Interfaces:**
- Produces:
  - `augment_refs(refs: Tensor (B,K,1,64,64), mask: Tensor (B,K)) -> Tensor` (same shape). Applies random erode/dilate (max-pool or min-pool with kernel 3, applied 0–1 times), mild elastic warp, ±5° rotation and ±2 px shift, only to masked-in refs.
  - `StyleEncoder(dim: int = 256)`, with `forward(refs (B,K,1,64,64), ref_ids (B,K), ref_mask (B,K)) -> (B,256)`. A per-ref CNN plus a char embedding, then a masked mean.
  - `GlyphUNet(style_dim: int = 256, n_chars: int = 52, base: int = 64)`, with `forward(x_t (B,1,64,64), t (B,) float in [0,1], char_id (B,), style (B,256)) -> (B,1,64,64)`. The conditioning (sinusoidal t + char embedding + style) is applied via adaptive GroupNorm in every res block.
  - `NULL_STYLE`: a learned vector used when the style is dropped (for CFG).

### Task 5: Flow-matching loss, sampler and training script

**Files:**
- Create: `typefaze/flow.py`, `scripts/train.py`
- Test: `tests/test_flow.py`

**Interfaces:**
- Consumes: `GlyphDataset`, `augment_refs`, `StyleEncoder`, `GlyphUNet`, `NULL_STYLE`
- Produces:
  - `flow_matching_loss(unet, encoder, batch: dict, p_drop: float = 0.1) -> Tensor`. MSE between `unet(x_t, t, target_id, style)` and `x1 − x0`, with t ~ U(0,1). Refs are augmented before encoding. With probability `p_drop` the style is replaced by `NULL_STYLE`.
  - `sample(unet, style (B,256), char_id (B,), steps: int = 12, cfg: float = 1.0) -> Tensor (B,1,64,64)` in [-1,1], using Euler from t=0 to 1. With `cfg > 1`, use v = v_null + cfg·(v_cond − v_null).
  - Checkpoint format: `{"unet": state_dict, "encoder": state_dict, "null_style": tensor, "step": int, "config": dict}`.
- CLI: `python scripts/train.py --data <dir> --out <dir> --batch 128 --lr 2e-4 --max-hours 11 --ckpt-minutes 20 --resume <ckpt?>`. Uses AMP and EMA (decay 0.999), and saves `ckpt_latest.pt`, `ckpt_ema.pt` and `samples_<step>.png` every `--ckpt-minutes`. The samples grid shows 8 val fonts: their 5 refs plus generated A–Z/a–z.
